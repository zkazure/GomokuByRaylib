#+TITLE: Gomoku By Raylib

write Gomoku with Raylib.

* Get Started

#+begin_src sh

* Rule

- board
  + 15x15
  + stones are placed on the intersections.
- black first
- five stones in a continuous horizontal, vertical, or diagonal line wins.

* Design

- LocalGameState

- PieceType:
  + empty

** UiPalette

界面颜色的唯一来源（~include/type.hpp~）。命名沿用设计系统里的 token 叫法，不是"棋子 / 棋盘"那套，
所以不能望文生义——含义看下表。

命名按**层**分，不是按用途：底色层（~background~ / ~surface~）、前景层（~foreground~）、专用色
（~accent~ / ~board~）；后缀 ~Disabled~ / ~Muted~ 表示同一层的变体。所以 ~foreground~ 既是文字色
也是线条与黑子的颜色。

| token | 值 (R,G,B) | 含义 | 用在哪 |
|---|---|---|---|
| background | 246,246,242 | 窗口底色 | ~ClearBackground~ |
| surface | 255,255,255 | 表面底色，同时是白子的颜色 | 按钮启用时的填充、白子 |
| surfaceDisabled | 224,224,224 | 禁用态表面 | 禁用按钮的填充 |
| board | 210,210,202 | 棋盘底色 | 棋盘矩形填充 |
| foreground | 24,24,24 | 主前景：文字与线条，同时是黑子的颜色 | 棋盘外框与网格线、黑子、正文与标题 |
| foregroundMuted | 105,105,100 | 次级前景 | 记分板的 ~SCORE~ 标签 |
| foregroundDisabled | 130,130,130 | 禁用态前景 | 禁用按钮的文字、边框与左侧竖条 |
| accent | 220,38,38 | 强调色 | 按钮左侧竖条、最近落子标记、对局结束的胜负文案 |

- 棋子与记分板图例共用 ~foreground~ / ~surface~，所以棋盘上的黑子与记分板里的黑子颜色一致。
- 原来的 ~border~ 是死变量且与前景色同值，已删除；边框实际由 ~foreground~（棋盘）与按钮的
  前景色变量承担。

** GlobalGame

泛指这个游戏相关的状态。

- screenLayout (default Vector2(800, 600))
- GameState
- boardBackground: 棋盘的背景颜色

** Player

一方棋手。既区分黑白棋手（持子），也区分这一方由谁操控，因此在网络对战中同样能说明对面是谁。

- playing: 持子，这一方在棋盘上下什么棋子（black / white）。
- type: 操控者类型（human / ai），随存档保存与恢复。
- score: 这一方自己的胜局数。归棋手所有，不再是"黑白一对整数"。
- name: 棋手名字，默认 ~player1~ / ~player2~，随存档保存与恢复。
  目前没有界面改名，要改就直接改存档最后一行（名字不含空白字符）。

- isAI: 是否由 AI 操控，等价于 ~type == PlayerType::AI~。
- 构造函数为 ~explicit~，避免 ~PieceType~ 被隐式转换成 ~Player~ 后悄悄丢掉操控者类型。

** LocalGame

特指棋盘的设置、落子状态以及操作历史。

- boardSize (default 15): standard board is 15 x 15.
  which determines how many rows and columns.
- state: playing, black_win, white_win, draw。
- blackPlayer / whitePlayer：两个棋手，各自带持子与操控者类型。
- currentPlayer：行棋方，指向 blackPlayer 或 whitePlayer 之一。
- boardState：棋盘上棋子的分布 (row, col).
- moveHistory: 上一步棋的历史
- rmoveHistory: 悔棋的历史

不变式：行棋方是**棋手本身**而不是颜色，当前该下什么棋子一律读 ~currentPlayer->playing~，
不另存一份颜色状态，所以不会与棋手自身漂移。~setCurrentPlayer()~ 与 ~nextTurn()~ 是唯一改写
~currentPlayer~ 的两个入口，其余代码只读。

注意：~currentPlayer~ 是指向 ~LocalGame~ 自身成员的裸指针，拷贝 ~LocalGame~ 后副本的指针仍指向
原对象的棋手。当前代码不存在拷贝点（~Board~ 只持有 ~LocalGame*~，AI 也只需要复制棋盘状态）；
若将来要做整局试算或联网同步，需先自定义拷贝，或改为存索引。

约定：**本局状态的判断与修改一律经由 LocalGame 的方法**。成员虽然是 public，但 ~Board~、
~main~、~menu~ 不直接访问 ~boardSize~ / ~state~ / ~boardState~ / ~moveHistory~ / ~rmoveHistory~ /
~currentPlayer~，一律走下面的查询与记账方法，避免同一份状态出现两条读写路径。

- Make1Move: 改变 boardState、moveHistory，然后 nextTurn。
- getLastMove: 拿到最近一步棋的相关参数，如果没有则返回一个 PieceType::EMPTY 的 Move。
- clear：清空棋盘，行棋方复位为黑棋；棋手的类型、名字与分数都保留
  （换一局不重置玩家选好的对手，也不清空累计比分）。
- setCurrentPlayer(color)：按持子颜色指定行棋方。
- nextTurn：把行棋方换成另一方。

判断：

- isPlaying：本局是否仍在进行（~state == playing~）。
- getState：本局胜负状态。
- canUndo / canRedo：还有没有可撤销 / 可重做的棋步。
- getBoardSize：棋盘边长。
- getPiece(row, col)：棋盘上某个交点的棋子。
- getCurrentPlaying：行棋方的持子，也就是现在该下什么棋子。
- isFiveAt(row, col, type)：把 ~(row, col)~ 视作已落 ~type~，沿横、竖、两条对角线四个方向取
  穿过该点的同色连续段，任一方向长度 >= 5 即为真。
  + 该点为空时即"假设在此落子"，该点已是同色子时即"按现状判定"，因此 ~checkOutcome~ 与 AI
    试算共用这一个方法，调用者不需要拿到 ~boardState~。
  + 该点已是对方向棋子、越界、或 ~type~ 为 empty 时返回 false。
  + 只认连续型：~3,4,5,6,8~ 这种中间断一格的五子不算胜。
- checkOutcome：取最近一手，先交给 ~isFiveAt~ 判成五，成五即置胜并返回；否则若 ~isBoardFull~
  为真则置平局。成五优先于平局，所以满盘上的制胜一手仍算胜。由 ~Game::update~ 每帧调用。
- isBoardFull：棋盘是否已满，判定依据是 ~moveHistory.size() >= boardSize * boardSize~。
- getScore(color) / addScore(color) / removeScore(color)：按棋手读写分数，~removeScore~ 不会扣成负数。
- getName(color) / setName(color, name)：按棋手读写名字。
- isPlayerAI(color)：某一方是否由 AI 操控。
- isCurrentPlayerAI：行棋方是否由 AI 操控。
- setPlayerType(color, type)：把某一方交给人或 AI，用于左侧面板的 ~BLACK: SWITCH~ / ~WHITE: SWITCH~ 按钮。

记账：

- undoMove：撤销一手，返回被撤的那一手。内部改动 boardState、两个历史栈、行棋方，并把
  ~state~ 复位为 playing。历史为空时返回一个 PieceType::EMPTY 的 Move。
- redoMove：重做一手，返回被重做的那一手。内部改动同样几处，并调用 ~checkOutcome~。

存档：

- saveToFile:
  #+begin_example
  boardSize
  state
  currentPlayer->playing（行棋方的持子颜色）
  boardState
  moveHistory.size()
  moveHistory
  rmoveHistory.size()
  rmoveHistory
  blackPlayer.type whitePlayer.type
  blackPlayer.score whitePlayer.score blackPlayer.name whitePlayer.name
  #+end_example
  最后两行都是后加的：前三行与前六个字段的语义一直没变，所以旧档仍能读，只是在末尾少几行。
  末尾按字段逐段解析——先读两个类型，再读两个分数，再读两个名字，**读到哪算哪，缺什么就保留
  内存里的现值**，所以"没有类型行的旧档""只有类型行的档""带分数与名字的新档"都能读。
- loadFromFile：读档后按存档里的持子颜色调用 ~setCurrentPlayer()~ 复位行棋方指针，再按末尾的
  字段恢复双方的操控者类型、分数与名字。**字段缺失时保留内存里当前的设置**，不覆盖成默认值——
  旧档没有表达对手偏好与比分，不该顺手把玩家选好的对手或累计比分改掉。

** Object

Everything which is visible in game is an ~object~.

- position: the middle of object

*** Board

- globalGame: 全局游戏的设置
- localGame: 本局棋局的设置
- ratio (default 3/4): 相对于获取的 windowLayout，这个 board 比例。
- width: 根据所在的 window 大小决定实际棋盘显示的宽度。
- cellWidth: 根据 width, size 计算得到每一格的宽度。
- leftTop: 棋盘左上方点的坐标
- intersections: 棋盘上每一个交点的坐标。外围一圈是距离无限大的。
  [1-boardSize] 为实际的可落子区域
- pieces: 实际棋子


- pos2coor: convert position on screen to coordinate on the board.
- coor2pos
- createPiece: 同时调用 localGame->make1Move。
- undo：悔棋。记账交给 ~localGame->undoMove()~（行棋方由它复位到被撤那一手所属的棋手），
  Board 只负责删除对应的 Piece 对象，并按被撤掉的胜负回滚 globalGame 的分数。
- redo: 取消悔棋。记账交给 ~localGame->redoMove()~（内部会重新判定胜负），Board 只负责重建
  Piece 对象并按新的胜负结算分数。
- clear：清空棋盘

** Game

游戏本体，持有本局的全部对象，把主循环拆成更新与绘制两个阶段。

- globalGame / localGame / board：本局的状态与棋盘。
- 八个 Button：左侧两个切换黑白双方的操控者，右侧六个是对局操作。
- ScoreBoard、WinLossDeclare：右侧面板。
- 右侧按钮从上到下：UNDO、REDO、SAVE GAME、LOAD GAME、NEW ROUND、NEW GAME。
  NEW ROUND 只清棋盘、**保留比分**（一局结束后的续局）；NEW GAME 连比分一起归零（开新的一场）。
  两者都保留棋手的操控者类型与名字——那是玩家设置，不属于这一局的状态。NEW GAME 始终可点。
- aiWaitTimer：AI 思考计时，进入 AI 回合后累计帧时间。
- 成员声明顺序即构造顺序：globalGame、localGame 先于 board（board 要用 screenLayout 与 boardSize
  算 cellWidth），scoreBoard / winLossDeclare 持有二者指针，排在最后。

- shouldClose：窗口是否被要求关闭。
- update：一帧的逻辑，不碰任何绘制。依次做
  + 刷新按钮启用态（undo / redo 看历史，NEW ROUND 看本局是否结束，NEW GAME 始终可点）。
    两个切换按钮的文案是固定的 ~BLACK: SWITCH~ / ~WHITE: SWITCH~，当前是谁在操控由记分板显示
  + 处理按钮点击；有按钮吃掉这次点击就到此为止
  + 全局状态为 GAMEOVER 时到此为止
  + 判定胜负并计分
  + 人类点击落子（轮到 AI 时忽略鼠标）
  + AI 回合：累计 ~aiWaitTimer~，满 ~AI_THINK_DELAY~（0.35s）才落子；不在 AI 回合时清零
- playAIMove：问 ~AI::chooseMove~ 要一步，走 ~board.createPiece~ 落子；万一非法就线性找一个空点兜底。
- render：BeginDrawing、画棋盘与右侧面板、EndDrawing。不画"轮到谁"的提示——行棋方由棋盘上
  最后一手的标记与记分板那一行体现，AI 是不是在思考看它下一手落下来即可。

人机对弈的几条约定：

- 黑白双方的操控者各由一个按钮切换（左侧的 ~BLACK: SWITCH~ / ~WHITE: SWITCH~，走
  ~localGame.setPlayerType~），对局中也可切，点击即时生效。
- 双方都是 AI 时对局自己走下去，直到分出胜负或平局。~AI::chooseMove~ 对空盘返回天元，
  所以黑方是 AI 时也能先行，不需要人类先摆一手。
- 人类落子有门禁：轮到 AI 时忽略鼠标，人类无法替 AI 落子，也不会与 AI 在同一帧各下一手。
- UNDO 一律**只撤一手**，不看对方是人还是 AI。撤销后行棋方回到被撤那一手的持有者
  （`undoMove()` 的行为），所以撤掉的若是 AI 的应手，下一步仍是 AI。
- 于是 PVE 下按 UNDO 常常"看不出变化"：AI 会在 0.35s 后把这一手重新下回来（同一局面决策是
  确定的）。想真正撤掉自己那一手，先把 AI 那侧切回 `HUMAN` 再按 UNDO。
- 胜负与计分仍由 ~update~ 判：谁成五就给**那个棋手**加分（~localGame.addScore~），
  悔棋时给对应棋手回滚（~removeScore~）；平局只把全局状态置为 GAMEOVER，双方都不加分。

~main~ 只负责窗口与循环骨架：

#+begin_src cpp
int main() {
    const Vector2 screen = {800, 600};

    InitWindow(screen.x, screen.y, "Gomoku By Raylib");
    SetTargetFPS(60);

    Game game(screen);

    while (!game.shouldClose()) {
        game.update();
        game.render();
    }

    CloseWindow();

    return 0;
}
#+end_src

窗口尺寸由 ~main~ 持有并传给 ~Game~，不在两处重复写死。循环是先 update 后 render，
所以点击的效果当帧就会画出来。

** AI

单步启发式的落子决策，取数一律经由 ~LocalGame~ 的查询方法。

#+begin_src cpp
namespace AI {
    constexpr int NEIGHBOR_RADIUS = 2;

    Coordinate chooseMove(const LocalGame& game);
    std::vector<Coordinate> candidateMoves(const LocalGame& game);
}
#+end_src

- chooseMove：为**当前行棋方**决策，棋子颜色取 ~game.getCurrentPlaying()~，所以黑白都能用。
  只读 ~game~，不调用 ~make1Move~，不污染历史与行棋方。
- candidateMoves：空盘只给天元；否则给所有"空点且 5×5 邻域内有棋子"的点。
  若这样的点一个都没有（棋盘已满），退化为所有空点；真的无点可下时 ~chooseMove~ 返回 ~(0,0)~，
  由调用方按非法落子处理。
- 棋型识别与打分是 ~src/ai.cpp~ 内部的 static 函数，不进头文件。

打分的棋型等级（把落点视作已落该色，沿横、竖、两条对角线各取连续同色段）：

| 条件 | 等级 | 分值 |
|---|---|---|
| 长度 >= 5 | FIVE | 1000000 |
| 长度 4，两端空 | OPEN_FOUR | 100000 |
| 长度 4，一端空 | FOUR | 10000 |
| 长度 3，两端空 | OPEN_THREE | 8000 |
| 长度 3，一端空 | THREE | 800 |
| 长度 2，两端空 | OPEN_TWO | 400 |
| 长度 2，一端空 | TWO | 40 |
| 长度 1 | ONE | 4 |

一个点的分值 = 四个方向的等级分值相加，双活三、四三这类组合由累加自然体现。

决策顺序：

1. 自己能在某点成五 → 直接取胜。
2. 否则对手能在某点成五 → 堵，多个堵点取对自身价值最高者。
3. 否则取 ~11 * 攻分 + 10 * 守分~ 最高者；同分按"离天元曼哈顿距离更近、行更小、列更小"决胜，
   以保证同一局面决策可复现。

第 1、2 步直接复用 ~LocalGame::isFiveAt~。第 3 步的权重是实测定的：攻 10 守 11 时 AI 自对弈
225 手填满棋盘和局，改成攻 11 守 10 后 90 手分出胜负——"立即成五必须堵"已由第 2 步保证，
第 3 步防守权重压过进攻只会让 AI 一路被动。

已知简化：

- 只看一步，无搜索、无迭代加深，对双三、双四的组合威胁可能只顾一头。
- 只识别连续型，不认 ~_XX_X_~ 这类跳型，可能漏防跳四。
- 不判禁手（游戏本身也没有禁手规则）。
- 单档强度；分值表与两个权重都是 ~src/ai.cpp~ 顶部的常量，调参成本低。
